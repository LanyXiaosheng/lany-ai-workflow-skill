# AI 工作流设计技能说明

`lany-ai-workflow-skill` 把重复手工任务转成可检查的人机协作流程，交付步骤合同、上下文清单、人工审核点、恢复方式和试跑方案。

## 什么时候用

经常重复整理同类材料，想判断哪些步骤可交给 AI；流程总跳步或扩域；自动化做了很久却没省下时间。只想建笔记目录时用知识工作流技能；具体修代码按对应开发任务处理，不强制经过本技能。

## 给什么材料

一份真实输入、原手工步骤、合格输出样例、耗时和频率；已有失败记录也可直接提供。不需要先选择模型或搭复杂代理团队。

## 调用示例（虚构演示）

```text
$lany-ai-workflow-skill
我每周两次把客户访谈整理为需求清单，每次30分钟。初稿中经常把我的推断当成客户原话。这里只给设计，不改文件或账户。请设计一个有人工验收的小流程，并算是否值得做。
```

## 示例产物（方案，尚未运行）

- 先检查一份访谈是否有来源、说话人及可定位段落；缺失就标待补，不猜说话人。
- AI 提取“原话位置、问题场景、明确需求”，另列推测；不能让推测混进客户陈述。
- 人对照原文审核：抽取是否失真、推测是否有依据、需要什么追问。
- 审核后输出需求清单；内容未过关时不进入精排版。
- 状态记录输入标识、已审段落、输出位置及待确认项，中断后继续核对而非重复生成已审条目。
- 试跑一个普通样例和一个说话人缺失样例。结果只在实际执行后填写。

假设搭建花120分钟，自动化后每次仍需12分钟人工检查、3分钟平均返工，则每次净省15分钟；不计维护时需8次，按每周两次约4周。费用和维护尚未知，这是测算示例，不是实测收益。若总人工时间仍为30分钟以上，应保留手工方法或重新选择环节。

本例没有发消息、读取真实客户资料或修改系统。用户授权落地后，才在其给定范围内运行与验收。

## 你会拿到什么

1. 最适合本轮处理的一个环节及理由。
2. 输入、处理、输出、完成标准、例外和人机分工。
3. 必要资料与恢复状态设计。
4. 试跑、停止和成本判断方法；实际运行时附真实结果。

## 独立仓库与安装

```bash
skill_dir="${CODEX_HOME:-$HOME/.codex}/skills"
mkdir -p "$skill_dir"
git clone https://github.com/LanyXiaosheng/lany-ai-workflow-skill.git "$skill_dir/lany-ai-workflow-skill"
```

已有同名目录时先比较与备份，不覆盖本地修改。客户端发现技能后，使用 `$lany-ai-workflow-skill` 调用。
